# PLAN B
### 이 순간, 당신의 플랜 B는? — 월드컵 명경기, 감독의 승부수

> DAKER 월간 해커톤 · "내가 축구 감독이라면 - 월드컵 전술 웹서비스 챌린지" 제출 기획서
> 팀: 개인 참가 (kirito2056) · 문서 버전 v0.1 (2026-07-22)

---

## 1. 서비스 개요

**한 줄 정의**
> 월드컵 명경기의 **결정적 순간에서 시간을 멈추고**, 내가 감독이 되어 전술·선수를 바꾸면 그 선택이 **실시간 지표와 분기된 결과로 되돌아오는** What-if 전술 시뮬레이터.

**문제의식**
축구를 보는 모든 사람은 감독이다. "저 선수 왜 안 빼?", "3백으로 가야지." 하지만 그 상상은 늘 머릿속에서 끝난다. 기존의 전술 보드 서비스는 선수를 놓기만 할 뿐, **내 선택이 경기에 어떤 영향을 주는지 즉시 보여주지 못한다.**

**핵심 가치**
`PLAN B`는 세 가지를 한 흐름에 담는다.
1. **개입(Intervene)** — 실제 명경기의 그 순간으로 들어가 감독의 결정을 내린다.
2. **반응(Feedback)** — 선수를 옮기는 *찰나*에 압박 라인·커버리지·기대득점(xG)이 실시간으로 꿈틀거린다.
3. **분기(Diverge)** — "휘슬"을 불면 내 전술 점수에 따라 경기 결과가 갈리고, 원래 역사와 비교된다.

**왜 'PLAN B'인가**
플랜 A는 이미 실패했다 — 0-1로 지고 있으니까. 감독이 진짜 시험받는 건 계획이 틀어진 그 순간, **두 번째 수를 두는 능력**이다. 이 서비스는 바로 그 "PLAN B"를 두는 경험이다.

**차별점 요약**
| 기존 전술 보드 | PLAN B |
|---|---|
| 빈 그라운드에 선수 배치 | **실제 명경기의 특정 순간**에서 시작 |
| 배치해도 아무 반응 없음 | 배치 즉시 **지표가 실시간 반응** |
| 결과 없음 | 선택이 **분기된 결과**로 연결 (원래 역사 vs 나의 역사) |
| 정적 이미지 | **FIFA 게임 룩앤필**의 동적 인터랙션 |

## 2. "감독 경험" 설계 의도

이 서비스가 파는 것은 기능이 아니라 **감정**이다. "내가 감독이다"라는 몰입을 만들기 위한 세 가지 설계 원칙:

**① 낮은 진입장벽, 즉각적 손맛**
- 로그인·튜토리얼 없이 3초 안에 그라운드가 뜬다.
- 선수는 그냥 **잡아서 끌면(drag)** 움직이고, 놓는 순간 지표가 반응한다. 설명이 필요 없다.

**② 결정의 무게감**
- 명경기의 "그 순간"이라는 맥락이 결정에 무게를 준다. 빈 필드에 4-3-3을 그리는 것과, *0-1로 지고 있는 후반 78분에 공격수를 넣는 것*은 완전히 다른 경험이다.
- 교체 카드는 3장 제한 등 실제 제약을 넣어 "선택"을 만든다.

**③ 반응의 카타르시스**
- 휘슬 → 슬로우모션 → 골 애니메이션 → 스코어 전환. 내 결정이 결과로 돌아오는 순간을 **연출**한다.
- 결과 후 "원래 역사에서는 이랬습니다" 오버레이로 감정적 대비를 만든다.

## 3. 핵심 인터랙션 명세

가장 중요한 평가 항목(감독 경험 25점 + 완성도 25점)이 여기서 결정된다. **하나하나가 버그 없이 매끄럽게** 동작하는 것을 최우선으로 한다.

### 3.1 전술 보드 (핵심 화면)
- **드래그 배치**: 선수 토큰을 그라운드 위 어디든 끌어 배치. 스냅 없이 자유 배치하되, 포지션 라인(수비/미드/공격) 가이드는 은은하게 표시. **GK는 드래그 잠금**(룰 엔진의 GK/필드플레이어 구분 전제를 보호).
- **포메이션 프리셋**: 4-3-3, 3-4-3, 4-2-3-1 등 버튼 클릭 시 선수들이 **부드럽게 슬라이드**해 재배치 (framer-motion). 선수→슬롯 매핑은 **동일 role → 같은 대분류(pos) → 남은 선수** 순의 결정론적 규칙으로 배정.
- **선수 카드**: 각 토큰은 FIFA식 카드 — 오버롤 숫자, 포지션, 능력치(속도/패스/수비 등). 호버 시 상세.
- **교체(Substitution)**: 벤치 선수를 그라운드로 드래그하면 교체. 교체 슬롯 제한. **투입 선수는 빠진 선수의 좌표·role을 승계**(이후 자유 이동 가능).
- **모바일 터치**: 1차 심사가 대중투표인 만큼 터치 드래그를 1급 시민으로 취급 — dnd-kit 터치 센서 적용, 폰에서의 히트맵 성능·드래그 손맛을 초기부터 검증.

### 3.2 실시간 지표 오버레이 (차별화 핵심)
선수를 놓을 때마다 **다시 계산 → 부드럽게 리렌더**:
- **압박 라인(Press Line)**: 팀의 수비 시작 높이를 라인으로.
- **커버리지 히트맵**: 각 선수의 영향권을 겹쳐 그린 열지도 (canvas). 빈 공간이 붉게/파랗게 드러남.
- **기대 지표**: 우리 팀 예상 xG, 실점 위험도, 밸런스(공격↔수비) 게이지.

### 3.3 휘슬 & 결과 분기
- **휘슬 버튼** → 현재 전술을 룰 엔진에 통과 → 종합 점수 산출.
- 점수 구간에 따라 **결과 시나리오 분기** (예: 극적 역전 / 무승부 / 그대로 패배).
- 슬로우모션 + 골 세리머니 + 스코어보드 전환 연출.
- 결과 후 **"실제 역사 vs 나의 역사"** 비교 + AI 감독 총평(§7).

### 3.4 AI 수석코치 코멘트 (양념)
- 전술 확정 시 "AI 수석코치"가 한 줄 브리핑 (예: "왼쪽 측면이 비었습니다. 상대 윙어가 파고들 겁니다.").
- **미연시(비주얼 노벨) 방식**: 사전 작성한 코멘트 뱅크에서 엔진 지표 조건으로 선택(§9). LLM 미사용 — 지연 0, 장애 0, 항상 즉답.

## 4. 페이지 구성

간결한 4화면. 솔로 개발 일정에 맞춘 최소 구성이자, 흐름이 끊기지 않는 구조.

1. **인트로 / 시나리오 선택** — "당신이 감독이었다면?" 명경기 카드 목록에서 선택.
2. **브리핑** — 경기 상황(스코어·시간·상대 전술) 요약. "감독 부임" 버튼.
3. **전술 보드 (메인)** — §3의 모든 인터랙션이 일어나는 곳.
4. **결과 & 공유** — 분기 결과 연출 → 원래 역사 비교 → 리더보드 등록 → 전술 카드 공유.

## 5. 데이터 활용 방식

대회 규정(더미 데이터 직접 구성 권장, 실명 참고 가능)에 따라 **로컬 JSON**으로 구성. 엔진은 하나이고 시나리오는 데이터로만 추가되므로, **명경기 라이브러리**를 손쉽게 확장할 수 있는 구조로 설계한다.

- **`data/matches/{id}/match.json`** — 명경기 시나리오: 라인업 좌표, 스코어·시간, 상대 전술 프로필, 분기 결과 규칙, 브리핑 텍스트.
- **`data/matches/{id}/players.json`** — 이 경기 양 팀 선수 능력치(속도/슈팅/패스/드리블/수비/피지컬). 실제 선수 이름·포지션·국가를 참고해 직접 구성.
- **시나리오 목표: 총 7경기.** 우선 아래 3경기를 완성도 높게 런칭하고, 동일 스키마로 최대 7경기까지 확장한다.
- 시나리오 훅은 두 갈래다. **"역사를 바꿔라"**(실제로 졌거나 비긴 경기 — 우루과이·이탈리아전)와 **"기적을 재현하라"**(실제가 극적 승리인 경기 — 포르투갈전). 결과 화면의 "실제 역사 vs 나의 역사" 비교는 두 경우 모두 성립한다 — 전자는 대비의 카타르시스, 후자는 "당신이라면 그 기적을 재현할 수 있었을까?"라는 도전.

| # | 시나리오 | 상황 | PLAN B 포인트 |
|---|---|---|---|
| 1 | **2022 한국 vs 포르투갈** | 후반, 0-1 열세 | 실제 역사가 기적의 2-1 역전승 → **"당신이라면 재현할 수 있었을까?"** (재현 챌린지) |
| 2 | **2022 한국 vs 우루과이** | 무득점 교착 | "한 골이 필요했던" 공격 전환의 아쉬움 |
| 3 | **2002 한국 vs 이탈리아** | 연장 승부 | 골든골 레전드 감성, 극한의 한 수 |
| 4~7 | (확장) | — | 브라질 vs 독일 7-1, 기타 명경기 등으로 볼륨 확대 |

- 특정 연도·대회 제한 없음(규정). **외부 API 미사용**(심사자 키 문제 회피). AI 코멘트도 사전 작성 코멘트 뱅크로 클라이언트에서 해결(§9).

## 6. 주요 사용 흐름 (유저 시나리오)

> **상황**: 2022 카타르 월드컵, 0-1로 뒤진 후반 78분. 당신은 감독이다.

1. 인트로에서 "한국 vs ○○ — 후반 78분, 0-1" 카드를 고른다.
2. 브리핑: "상대는 내려앉아 걸어 잠갔습니다. 15분 안에 한 골이 필요합니다."
3. 전술 보드 진입. 수비형 미드필더를 빼고 공격수를 **드래그로 투입** → 순간 xG 게이지가 오르고, 동시에 실점 위험도도 붉게 오른다.
4. 라인을 끌어올려 압박 라인을 전진 → 커버리지 히트맵의 빈 공간이 상대 진영으로 이동.
5. "이 정도면 승부수다." **휘슬**을 분다.
6. 슬로우모션 → 후반 89분 극장골 → **2-1 역전** 연출.
7. "실제 역사에서도 대한민국은 2-1 극장 역전승 — 당신은 그 기적을 당신의 방식으로 재현해냈습니다." 오버레이. AI 총평: "리스크를 감수한 전진 압박이 적중했습니다. 그날의 답과 당신의 답을 비교해 보세요."
8. 리더보드에 내 전술 점수 등록, 전술 카드 이미지 공유.

## 7. 시스템 아키텍처 & 기술 스택

**코어는 100% 클라이언트**. 시뮬레이션·지표·코멘트 전부 브라우저에서 동작하므로 **서버가 죽어도 앱이 동작**한다 (완성도 방어). 백엔드는 리더보드(여유 기능)를 붙일 때만 존재한다.

```
[브라우저 · React(Vite) SPA — 코어 100% 클라이언트]
  ├─ localStorage: 내 전술/설정 저장 (로그인 없음)
  ├─ 룰 기반 시뮬레이션 엔진 (핵심, 항상 동작)
  ├─ 코멘트 뱅크: 엔진 지표 조건 → 사전 작성 코멘트 결정론 선택 (LLM 미사용)
  ├─ canvas 히트맵 / framer-motion 애니메이션 / dnd-kit 드래그
  │
  └─(리더보드 채택 시에만, fetch /api/*)→ [n150 개인서버]
        ├─ Caddy   : 정적 파일 서빙 + 리버스 프록시 (자동 HTTPS)
        └─ FastAPI : POST /api/tactics · GET /api/leaderboard (SQLite)
                     익명 세션 쿠키(uuid, httponly) — 로그인 없이 식별
  [Cloudflare Tunnel] → 안정적 공개 HTTPS URL (심사 기간 8/18까지 유지)
```

- **프론트**: React + Vite + TypeScript, 상태 `zustand`, 드래그 `dnd-kit`, 애니메이션 `framer-motion`, 히트맵 `canvas`.
- **백엔드(여유 기능)**: 리더보드를 채택할 때만 Python FastAPI + `SQLite`. 코어 앱은 백엔드 없이 완결 — 최악의 경우 순수 정적 배포로도 심사 가능.
- **저장소**: 클라 저장 `localStorage`.
- **배포**: n150 개인서버 + Cloudflare Tunnel + Caddy + systemd(자동 재시작). 정적 서빙만으로 시작.

> **핵심 원칙**: 로그인·결제 없이 심사 가능 / 심사자 키 없이 접근 / 동적 기능은 클라에서 항상 동작 / 배포 URL 8/18까지 상시 접근.

## 8. 룰 기반 시뮬레이션 엔진 (완성도의 핵심)

LLM 없이도 결과가 나오는 **결정론적 규칙 엔진**. 재현 가능하도록 시드 기반.

- 각 선수의 배치 좌표 × 능력치 → 라인별 밀도·밸런스 계산.
- 팀 종합 스탯: `공격력`, `수비력`, `압박도`, `밸런스`, `리스크`.
- 상대 전술과의 상성 가중 → `xG`, `실점확률` 산출.
- 종합 점수 → 결과 시나리오 분기 매핑 (시드 고정으로 동일 전술 = 동일 결과).
- **이 점수가 곧 리더보드 랭킹 점수.**

## 9. AI 수석코치 코멘트 — 사전 작성 코멘트 뱅크 (LLM 미사용)

미연시(비주얼 노벨)처럼 **상황별 코멘트를 수십 개 사전 작성**해 두고, 엔진 지표 조건으로 선택한다. 엔진이 이미 정확한 전술 상태(압박도·커버리지 갭 위치·리스크)를 알고 있으므로, 조건 매칭 코멘트가 LLM보다 오히려 정확하다.

- **구조**: 각 코멘트 = `조건(엔진 출력 기반) + 우선순위 + 문장 변주 목록`. 조건 매칭 중 우선순위 최상위를 선택, 변주는 라인업 해시 시드로 결정론적으로 선택(같은 전술 = 같은 코멘트).
- **분량 목표**: 공통 뱅크 30~40줄(전술 브리핑 + 결과 총평) + 시나리오별 전용 10줄 내외. 전부 데이터(JSON)라 코드 수정 없이 추가·퇴고 가능.
- **효과**: 외부 의존성 0 · 지연 0 · 한국어 품질 상시 보장 · 심사 중 "동적 기능 미작동" 리스크 원천 차단. API 키 이슈도 소멸.
